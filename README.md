当前开发范围：列车自动制动机简略试验。

- 确认列车管定压稳定
- 自阀减压 100 kPa
- 记录并判断列车管排风时间
- 保压 1 min 并检查漏泄
- 查询尾部风压并确认最后一辆车制动作用
- 自阀回运转位，确认尾部风压恢复和最后一辆车缓解
- 桌面端及手机横屏操作

## 试验判定与记录单

试验结论与操作评分是**两条独立的口径**，记录单上分列呈现：

- **试验结论**（合格 / 不合格）只由物理判定决定：列车管定压、减压量、排风时间、保压时间、
  列车管漏泄量、列尾制动确认、列尾缓解确认七项。
- **操作评分**（百分制）只反映操纵规范程度：流程完成 60、一次减压到位 15、排风时间判断 15、
  列尾查询效率 10，再扣无关设备操作分（每次 3 分，上限 15 分）。分高不等于试验合格。

流程走完或中止时会自动出具记录单（也可点「查看试验记录单」重新打开），支持复制纯文本与打印/另存 PDF。

异常工况的处置原则：

| 异常 | 处置 |
|---|---|
| 排风时间过短 / 过长 | 流程照常走完（仍须确认制动与缓解作用），但结论判**不合格**并给出检查方向 |
| 保压漏泄超限 | 直接判不合格并中止，提示查明漏泄处所 |
| 尾部风压持续不跟随（连续 4 次查询且超过 20 s） | 判定列车管未贯通，判**不合格**并中止，避免学员无限重查 |

## 界面布局

- **画面下方风压条**：总风 / 均衡风缸 / 列车管 / 尾部风压 / 制动缸 / 保压剩余 排成一排常显，
  叠在画面下层，**手机全屏（沉浸式）下也一定可见**；风压条左端是「列尾查询 · CIR」按钮。
- **右侧可缩进抽屉**：简略试验流程、试验操作台、教学场景选择全部收进右侧抽屉，
  点右侧竖排标签「流程 / 操作台」展开、再点一下收起（按 Esc 也可收起）。
  抽屉**刻意不做全屏遮罩**——展开时仍能直接操作驾驶台，便于「边看流程边操作」。
- **CIR 列尾查询装置**（机车综合无线通信设备）：点驾驶台左侧显示单元的 CIR 热区，
  或点风压条上的「列尾查询 · CIR」，都会打开 CIR 面板，可查询列尾风压、获取尾部制动/缓解反馈。
  因此列尾动作有两个等价入口（CIR 面板 / 抽屉里的操作台按钮）。
  热区位置是 `scripts/archive-2d-cabview-real-route.js` 顶部的 `CIR_HOTSPOT` 常量，
  与实际设备位置不符时只改这一处。

## 教学场景与考核抽考

页面「试验操作台」顶部有 **教学场景（教师用）** 选择器，随时可切换，切换即开始新一轮：

| 选项 | 含义 |
|---|---|
| 正常 · 标准编组 | 无故障，用于讲解与练手 |
| 排风时间过短 | 注入：排风时间短、尾部风压响应迟缓 |
| 排风时间过长 | 注入：排风时间长、与编组不符 |
| 保压漏泄超限 | 注入：列车管漏泄量超过允许值 |
| **考核抽考（不告知）** | 现场按权重随机抽一种，**考试过程中不告诉学员抽到了什么** |

考核抽考概率（改难度改 `scripts/brakeTestScenarios.js` 的 `EXAM_DRAW_WEIGHTS`）：

```
normal 50%    short 20%    long 20%    leak 10%
```

考核模式的要点：

- 考试过程中「本轮场景不告知」，学员只能凭排风时间、漏泄量、列尾风压自行判断；
- 「重新开始本轮试验」**沿用本轮已抽到的场景，不重新抽签**，保证同一场考核前后一致；
- 最终记录单写明 **「考核抽考 · 本轮实际注入：…」**，便于教师事后核对追溯（复制出的纯文本同样带此标注）。

## 参数

- `?scenario=normal|short|long|leak`：直接指定场景（教师演示用）
- `?scenario=exam`：直接进入考核抽考模式（可做成书签当考核入口）
- `?debug=1`：保压时间由 60 秒缩短为 6 秒，仅用于开发调试；
  记录单上会标注「调试模式，不得作为正式记录」
- 两者可叠加，如 `?debug=1&scenario=exam`
- 参数写错（如 `?scenario=foo`）不会静默忽略：页面红字提示已回落到「正常 · 标准编组」
